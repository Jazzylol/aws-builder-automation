# 验证码功能修复说明

## 问题原因

所有账号获取验证码都失败，提示"该账号的邮箱 Token 已失效"。

**根本原因**：
- 注册 Kiro 账号时，使用了 SSO 的 `client_id` 和 `client_secret`
- 这些 SSO 凭证覆盖了原来用于邮箱 OAuth2 的凭证（存储在 `client_id` 和 `refresh_token` 字段）
- 导致获取验证码时用的是 SSO 凭证而不是邮箱凭证，所以失败

## 解决方案

### 1. 数据库改动（已完成）

添加了两个新字段用于备份邮箱 OAuth2 凭证：
- `email_client_id`: 邮箱 OAuth2 的 client_id
- `email_refresh_token`: 邮箱 OAuth2 的 refresh_token

### 2. 注册流程改动（已完成）

在注册前会自动备份原始邮箱凭证：
```rust
// 备份原始邮箱 OAuth2 凭证（如果还没有备份）
if account.email_client_id.is_none() {
    let conn = db.0.lock().map_err(|e| e.to_string())?;
    database::backup_email_credentials(&conn, account_id, &account.client_id, &account.refresh_token)
        .map_err(|e| e.to_string())?;
}
```

### 3. 获取验证码逻辑改动（已完成）

优先使用备份的邮箱凭证：
```rust
// 优先使用备份的邮箱凭证，如果没有则使用当前的
let (email_client_id, email_refresh_token) = if let (Some(cid), Some(rt)) = (&account.email_client_id, &account.email_refresh_token) {
    eprintln!("[验证码] 使用备份的邮箱 OAuth2 凭证");
    (cid.clone(), rt.clone())
} else {
    eprintln!("[验证码] 使用当前的 OAuth2 凭证");
    (account.client_id.clone(), account.refresh_token.clone())
};
```

### 4. 错误重试逻辑（已完成）

遇到 `invalid_grant` 错误时最多重试 1 次就跳过：
```rust
if error_str.contains("invalid_grant") || error_str.contains("Token request failed") {
    token_error_count += 1;
    eprintln!("[验证码] ⚠️ Token 错误 ({}/2): {}", token_error_count, e);
    
    // 最多重试 1 次（共 2 次尝试）
    if token_error_count >= 2 {
        eprintln!("[验证码] ❌ Token 失效，跳过此账号");
        return Err(anyhow!("OAuth2 token 失效，请更新账号的 refresh_token"));
    }
}
```

## 对于已注册账号的处理方案

### 方案 A：重新导入原始数据（推荐）

1. 导出当前已注册账号的 Kiro 信息（邮箱、Kiro密码、Kiro Token）
2. 删除所有账号
3. 重新导入原始的邮箱数据（包含原始的邮箱 OAuth2 凭证）
4. 对于已有 Kiro 账号的，可以使用"提取 Token"功能重新登录

### 方案 B：手动更新数据库（需要原始数据）

如果你还保留着原始的邮箱 OAuth2 凭证，可以手动更新数据库：

```sql
UPDATE accounts 
SET email_client_id = '原始的邮箱client_id',
    email_refresh_token = '原始的邮箱refresh_token'
WHERE id = 账号ID;
```

### 方案 C：对于新注册的账号

从现在开始，所有新注册的账号都会自动备份邮箱凭证，不会再出现这个问题。
