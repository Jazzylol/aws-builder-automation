# SSO 授权链接功能使用说明

## 功能概述

这个功能允许你为已注册但没有 Kiro Token 的账号生成 SSO 授权链接，然后手动在已登录的浏览器中完成授权，最后通过轮询获取 RefreshToken。

## 适用场景

- **所有账号都可以使用**（无论是否注册成功）
- 想要手动完成 SSO 授权以获取 Token
- 适用于以下情况：
  - 未注册的账号，直接通过 SSO 授权获取 Token
  - 已注册的账号，首次获取 Token
  - Token 已过期需要更新
  - Token 失效需要重新获取
  - 想要在已登录的浏览器中快速授权

## 使用步骤

### 1. 生成授权链接

在账号列表的"SSO 授权"列中，**所有账号**都会显示"生成链接"按钮。

**操作**：
1. 点击"生成链接"按钮
2. 系统会自动生成 SSO 授权链接
3. 生成成功后会显示复制按钮和获取 Token 按钮

**优势**：
- 无需先注册 Kiro 账号
- 可以直接通过 SSO 授权获取 Token
- 适合批量处理多个账号

### 2. 复制授权链接

生成链接后，会显示两个按钮：
- **复制按钮**（📋图标）：复制授权链接
- **获取 Token 按钮**（🔑图标）：轮询获取 Token

**操作**：
1. 点击复制按钮
2. 系统会提示"SSO 授权链接已复制到剪贴板"

### 3. 在浏览器中完成授权

**重要**：必须在**已经登录了该 Kiro 账号**的浏览器中打开链接。

**操作**：
1. 打开已登录该账号的浏览器
2. 粘贴授权链接到地址栏
3. 按回车打开页面
4. 页面会显示授权确认界面
5. 点击"确认并继续"按钮
6. 点击"允许访问"按钮
7. 完成授权

### 4. 获取 Token

完成浏览器授权后，返回应用程序。

**操作**：
1. 点击"获取 Token"按钮（🔑图标）
2. 系统开始轮询获取 Token
3. 按钮会显示加载动画
4. 获取成功后会提示"成功获取 Token: xxx..."
5. 账号的 `kiro_refresh_token` 字段会自动更新
6. SSO 授权链接数据会自动清除

**注意**：
- 必须先在浏览器中完成授权，再点击"获取 Token"
- 如果授权未完成就点击，会提示获取失败
- 可以多次点击"获取 Token"重试

## 工作原理

### 1. 生成授权链接

```
后端操作：
1. 注册 SSO 客户端（获取 client_id 和 client_secret）
2. 获取设备授权码（device_code 和 user_code）
3. 生成授权链接（verification_uri_complete）
4. 返回所有必要信息

前端操作：
1. 保存授权链接和相关参数
2. 显示复制和获取 Token 按钮
```

### 2. 手动授权

```
用户操作：
1. 在已登录的浏览器中打开授权链接
2. 点击"确认并继续"
3. 点击"允许访问"
4. AWS SSO 服务器记录授权状态
```

### 3. 轮询获取 Token

```
后端操作：
1. 使用 device_code 轮询 AWS SSO 服务器
2. 检查用户是否已完成授权
3. 如果已授权，返回 RefreshToken
4. 更新数据库中的 kiro_refresh_token

前端操作：
1. 显示加载状态
2. 等待后端返回结果
3. 显示成功或失败提示
4. 刷新账号列表
```

- **复制按钮**（📋）：复制授权链接到剪贴板
- **获取 Token 按钮**（🔑）：绿色图标，轮询获取 RefreshToken

## 常见问题

### Q1: 未注册的账号可以使用 SSO 授权链接吗？

**可以！** 这是这个功能的一大优势。

**说明**：
- 不需要先注册 Kiro 账号
- 可以直接通过 SSO 授权获取 Token
- 获取 Token 后，账号状态会自动更新为"已注册"

**使用场景**：
- 跳过自动注册流程，直接手动授权
- 批量处理多个账号时更灵活
- 避免自动化注册可能遇到的问题

### Q2: 点击"获取 Token"后提示失败？

**可能原因**：
1. 还没有在浏览器中完成授权
2. 授权链接已过期
3. 网络连接问题

**解决方案**：
1. 确保先在浏览器中完成授权
2. 重新生成授权链接
3. 检查网络连接

### Q3: 授权链接在哪个浏览器中打开？

**重要**：必须在**已经登录了该 Kiro 账号**的浏览器中打开。

**原因**：SSO 授权需要验证当前登录的账号身份。

**建议**：
- 使用浏览器的隐私模式/无痕模式
- 每个账号使用独立的浏览器配置文件

### Q4: 可以批量生成授权链接吗？

**不可以**。每个账号需要单独生成授权链接，因为：
- 每个链接对应一个独立的 device_code
- 需要在对应账号的浏览器中完成授权
- 避免混淆不同账号的授权状态

### Q5: 授权链接有效期多久？

**通常为 15 分钟**。如果超时，需要重新生成链接。

### Q6: 获取 Token 需要等多久？

**取决于授权完成时间**：
- 如果已经完成授权：几秒钟
- 如果还未授权：会一直轮询直到超时或成功
- 建议先完成授权再点击"获取 Token"

## 与"提取 Token"功能的区别

| 功能 | 提取 Token | SSO 授权链接 |
|------|-----------|-------------|
| 自动化程度 | 全自动 | 半自动（需手动授权） |
| 浏览器控制 | 自动打开浏览器 | 手动在已登录浏览器中操作 |
| 适用场景 | 首次获取 Token | 已登录账号补充 Token |
| 验证码 | 自动获取 | 不需要 |
| 密码输入 | 自动输入 | 不需要 |
| 授权操作 | 需要手动点击 | 需要手动点击 |

## 技术细节

### 后端 API

```rust
// 生成 SSO 授权链接
generate_sso_auth_url() -> Result<String, String>
// 返回格式: url|||device_code|||client_id|||client_secret|||interval

// 轮询获取 Token
poll_sso_token(
    account_id: i64,
    device_code: String,
    client_id: String,
    client_secret: String,
    interval: u64
) -> Result<String, String>
```

### 前端 API

```typescript
api.generateSsoAuthUrl(): Promise<string>
api.pollSsoToken(
    accountId: number,
    deviceCode: string,
    clientId: string,
    clientSecret: string,
    interval: number
): Promise<string>
```

### 数据流程

```
1. 用户点击"生成链接"
   ↓
2. 后端注册 SSO 客户端
   ↓
3. 后端获取设备授权码
   ↓
4. 返回授权链接和参数
   ↓
5. 前端保存数据并显示按钮
   ↓
6. 用户复制链接到浏览器
   ↓
7. 用户在浏览器中完成授权
   ↓
8. 用户点击"获取 Token"
   ↓
9. 后端轮询 AWS SSO 服务器
   ↓
10. 获取 RefreshToken
   ↓
11. 更新数据库
   ↓
12. 前端刷新显示
```

## 最佳实践

1. **先完成授权再获取 Token**：避免不必要的等待和重试
2. **使用独立浏览器配置**：每个账号使用独立的浏览器配置文件
3. **及时获取 Token**：授权完成后尽快获取，避免链接过期
4. **检查网络连接**：确保网络稳定，避免轮询失败
5. **保存授权链接**：如果需要，可以先保存链接稍后使用

## 总结

SSO 授权链接功能提供了一种灵活的方式来为已注册账号获取 RefreshToken，特别适合在已经登录的浏览器中快速完成授权。相比全自动的"提取 Token"功能，这种方式更加可控，适合批量处理多个账号。
