# 批量注册防封禁改进说明

## 📊 问题分析

通过分析 `log1.md` 和 `log2.md` 日志文件，发现以下导致账号被批量封禁的核心问题：

### 🔴 问题1：姓名重复使用
**日志统计**：
- Li Qiang: 出现 3 次
- Wang Fang: 出现 3 次  
- Wang Lei: 出现 2 次
- Zhang Wei: 出现 2 次

**风险**：AWS 系统检测到多个账号使用相同姓名，判定为批量注册。

---

### 🔴 问题2：连续批量注册，无延迟
**日志特征**：
- 所有账号在**同一个浏览器会话**中连续注册
- 账号之间**没有任何延迟**
- 使用**相同的 client_id**（`9e5f94bc-e8a4-4e73-b...`）

**风险**：短时间内连续注册多个账号，明显的自动化特征。

---

### 🔴 问题3：相同的设备指纹
**日志特征**：
- 同一个浏览器实例
- 相同的 IP 地址
- 相同的设备特征（Canvas、WebGL、AudioContext 指纹）

**风险**：多个账号来自同一设备，触发风控系统。

---

### 🔴 问题4：操作速度过快且一致
**日志特征**：
- 每个步骤的延迟时间完全一致（2秒、3秒、4秒）
- 没有模拟真实用户的随机性
- 输入速度过快

**风险**：操作模式过于规律，不符合真实用户行为。

---

## ✅ 改进方案

### 1️⃣ 扩大姓名库并确保不重复

**改进内容**：
- 将英文名字库从 70 个扩大到 **150 个**
- 将英文姓氏库从 50 个扩大到 **100 个**
- 理论组合数：**150 × 100 = 15,000 种**
- 使用 `HashSet` 记录已使用的姓名，确保批量注册时不重复

**代码位置**：`src-tauri/src/commands.rs` - `generate_random_english_name()` 函数

**效果**：即使注册 100 个账号，姓名重复的概率也极低。

---

### 2️⃣ 账号之间添加随机延迟（60-180秒）

**改进内容**：
- 每个账号注册完成后，等待 **60-180 秒**（随机）再注册下一个
- 模拟真实用户的操作间隔
- 避免短时间内连续注册

**代码位置**：`src-tauri/src/commands.rs` - `start_batch_registration_by_ids_internal()` 函数

```rust
// 账号之间添加随机延迟（60-180秒）
if index < accounts.len() - 1 {
    let mut rng = rand::thread_rng();
    let delay_seconds = rng.gen_range(60..=180);
    eprintln!("[批量注册] ⏰ 等待 {} 秒后继续下一个账号...", delay_seconds);
    std::thread::sleep(std::time::Duration::from_secs(delay_seconds));
}
```

**效果**：
- 注册 5 个账号需要 **4-12 分钟**
- 注册 10 个账号需要 **9-27 分钟**
- 大大降低被检测为批量注册的风险

---

### 3️⃣ 操作步骤之间添加随机延迟

**改进内容**：
- 所有固定延迟（2秒、3秒、4秒）改为随机延迟
- 新增 `random_delay()` 辅助函数

**代码位置**：`src-tauri/src/commands.rs` - `perform_registration()` 函数

**延迟范围**：
| 操作步骤 | 原延迟 | 新延迟（随机） |
|---------|--------|---------------|
| 页面加载后 | 3秒 | 2-4秒 |
| 点击按钮后 | 4秒 | 3-5秒 |
| 输入文本后 | 2秒 | 1.5-2.5秒 |
| 等待页面响应 | 0.5秒 | 0.3-0.9秒 |
| 注册完成等待 | 5秒 | 4-6秒 |

**效果**：每个账号的注册时间不再完全一致，更接近真实用户行为。

---

### 4️⃣ 显示详细的批量注册进度

**改进内容**：
- 显示当前进度（例如：进度 3/10）
- 显示当前正在注册的账号邮箱
- 显示使用的随机姓名
- 显示等待时间和原因

**代码示例**：
```rust
eprintln!("========================================");
eprintln!("[批量注册] 进度: {}/{}", index + 1, total_count);
eprintln!("[批量注册] 当前账号: {}", account.email);
eprintln!("[批量注册] 使用姓名: {}", random_name);
eprintln!("========================================");
```

**效果**：用户可以清楚地看到批量注册的进度和状态。

## 📋 使用建议

### ⚠️ 重要提示

1. **分批注册**：建议每天只注册 **2-3 个账号**
2. **不同时间段**：避免在同一时间段连续注册
3. **更换 IP**：如果可能，使用不同的网络环境（VPN、代理）
4. **间隔时间**：两次批量注册之间至少间隔 **24 小时**

### 📊 推荐注册策略

| 账号数量 | 推荐方案 | 预计时间 |
|---------|---------|---------|
| 5 个账号 | 一次性注册 | 10-20 分钟 |
| 10 个账号 | 分 2 天，每天 5 个 | 2 天 |
| 20 个账号 | 分 7 天，每天 3 个 | 1 周 |
| 50 个账号 | 分 20 天，每天 2-3 个 | 3 周 |

## 🔧 技术细节

### 随机延迟函数

```rust
/// 生成随机延迟（模拟真实用户操作）
fn random_delay(min_ms: u64, max_ms: u64) {
    use rand::Rng;
    let mut rng = rand::thread_rng();
    let delay_ms = rng.gen_range(min_ms..=max_ms);
    std::thread::sleep(std::time::Duration::from_millis(delay_ms));
}
```

### 姓名去重逻辑

```rust
// 用于记录已使用的姓名，确保不重复
let mut used_names = std::collections::HashSet::new();

// Generate unique random English name (确保不重复)
let random_name = loop {
    let name = generate_random_english_name();
    if !used_names.contains(&name) {
        used_names.insert(name.clone());
        break name;
    }
};
```

## 📝 后续优化建议

如果仍然遇到封禁问题，可以考虑以下进一步优化：

1. **使用代理 IP**：每个账号使用不同的 IP 地址
2. **浏览器指纹伪装**：更深度的指纹随机化
3. **独立浏览器实例**：每个账号使用独立的浏览器进程
4. **更长的延迟**：将账号间隔延长到 5-10 分钟
5. **手动验证**：关键步骤（如 SSO 授权）改为手动操作
